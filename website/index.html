    Raise an SOS

    Field teams and local authorities can report an emergency here. The request is validated by the Java service layer, saved through the DAO into the database and instantly appears on the desktop dashboard with a toast notification.

    Live priority score — urgency + 10·log₁₀(people+1) + min(1.5·hours, 30) + 15·vulnerable
    • You get a tracking ID and SMS updates as help is dispatched
    • Server-side validation with a custom ValidationException
    • Stored with PreparedStatement (SQL-injection safe)
    • Observer pattern pushes it to the JavaFX UI in real time

    How the matching engine thinks

    A greedy, priority-driven algorithm built on Java Collections — explainable, fast and fair.

    01

    Triage

    Every active request gets a priority score from urgency, people affected, waiting time (ageing — no request starves) and vulnerable groups.

    02

    Queue

    Requests go into a PriorityQueue ordered by compareTo(). The engine always poll()s the most urgent one.

    03

    Match

    Candidate resources of the same type within the radius are sorted by a polymorphic matchCost() — distance, expiry, resource nature.

    04

    Dispatch

    Units are allocated greedily. Each request is committed in its own JDBC transaction — any failure rolls back cleanly.

    Layered architecture

    Clean separation of concerns — the database can move from SQLite to MySQL or the cloud without touching business logic.
